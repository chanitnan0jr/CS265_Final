## Core concepts

1. **SQLite CRUD & persistence (หน้า 2–8):** ตัวอย่าง `PhotoJournalSQLite` เก็บ `id` (PK), `title`, `description`, `imageBase64`, `createdAt`. `JournalItem` = data model; `JournalDbHelper` = `insert/update/delete/getById/getAll` โดยใช้ `ContentValues` และ `Cursor`. `getAll()` เรียง `createdAt DESC`. SQLite เก็บข้อมูลถาวรแม้ปิดแอป ต่างจากข้อมูลที่อยู่เฉพาะใน View.
2. **Activity → Database → UI (หน้า 3–4, 9–11):** `MainActivity` เปิด `AddEditActivity` เพื่อบันทึก แล้วโหลด SQLite ใหม่มาแสดงรายการ; เปิด `DetailActivity` หรือ Edit โดยส่ง **record ID** ผ่าน `Intent.putExtra()` จากนั้นอ่านรายการที่ต้องการด้วย ID.
3. **RecyclerView (หน้า 11–13):** `JournalAdapter` และ `ViewHolder` ผูกข้อมูลเข้าการ์ด; `onBindViewHolder()` กำหนดภาพ ชื่อ รายละเอียด เวลา และ Click listeners (`Open/Edit/Delete`). **SQLite เป็น source of truth; RecyclerView เป็น display** ต้องอัปเดต list เมื่อข้อมูลเปลี่ยน.
4. **Confirm delete (หน้า 10, 19):** `AlertDialog` ให้ Cancel/Delete; ลบใน SQLite *เมื่อยืนยันเท่านั้น* แล้ว `loadItems()` และแสดง Toast ว่าลบสำเร็จ (Toast เป็นผลหลังลบ ไม่ใช่ขั้นตอนยืนยัน).
5. **Activity Result + Images (หน้า 14–16):** `TakePicture` / `GetContent` รับภาพผ่าน `Uri`; Preview → แก้แนวตาม EXIF → ย่อ 80% → JPEG → Base64 → SQLite; `ImageUtils` ถอด Base64 เป็น Bitmap เพื่อแสดง. เป็นเพียงตัวอย่าง **image storage** ไม่ใช่รูปแบบบังคับสำหรับเสียงหรือข้อมูลทุกชนิด.
6. **Class responsibilities & exercise (หน้า 17–21):** `JournalItem` (model), `JournalDbHelper` (DB), `JournalAdapter` (list), `MainActivity` (รายการ), `AddEditActivity` (form), `ImageUtils` (ภาพ), `DetailActivity` (รายละเอียด). สไลด์ให้ทดลองเพิ่ม 2, แก้ 1, ลบ 1 รายการ และอธิบายเส้นทางข้อมูล.

## Example mechanism

```text
User form / Camera-Gallery URI
  → AddEditActivity → (ImageUtils for images) → JournalDbHelper
  → SQLite → getAll() → JournalAdapter → RecyclerView
  → Open/Edit: Intent carries ID → getById(ID)
  → Delete: AlertDialog confirm → SQLite delete → reload list
```
