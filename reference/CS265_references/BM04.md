## Key concepts

1. **Event-driven UI & listeners** (หน้า 2–3): Android รับปฏิสัมพันธ์ผ่าน UI objects เช่น `EditText` และ `Button`; เหตุการณ์หลักคือ **Key Event** (`ACTION_DOWN`/`ACTION_UP`, `KEYCODE_ENTER`), **Click Event** (`onClick`, `onLongClick`), และ **MotionEvent** (`ACTION_DOWN`, `ACTION_UP`, `ACTION_MOVE`, hover; ตำแหน่ง `getX()/getY()` และแรงกด `getPressure()`). สไลด์ยังกล่าวถึงการเปลี่ยนข้อความ/โฟกัส เช่น `onTextChanged`, `onFocusChanged`.
2. **Event listener → processing → UI output** (หน้า 4–8): ตัวอย่างคำนวณพื้นที่วงกลม: ฟัง Enter ด้วย `setOnKeyListener` หรือคลิก Calculate ด้วย `setOnClickListener` → อ่านรัศมีจาก `EditText` → ถ้าว่างแสดงคำเตือนจาก string resource; ถ้ามีค่า แปลงเป็น `double`, คำนวณ `πr²`, format ทศนิยม 4 ตำแหน่ง และแสดงใน `TextView`; ปุ่ม Clear ล้างทั้ง input/output. **ข้อจำกัด:** สไลด์แสดงการตรวจค่าว่าง แต่ไม่ได้แสดงการจัดการ input ที่ไม่ใช่ตัวเลขครบถ้วน.
3. **Passing data between Android Activities** (หน้า 9–16): `MainActivity` อ่านข้อความแล้วสร้าง **explicit `Intent`** ไป `DisplayActivity`, ส่งข้อมูลด้วย `putExtra(EXTRA_MESSAGE, message)` และเปิดหน้าด้วย `startActivity(intent)`; หน้าปลายทางรับด้วย `getIntent().getStringExtra(...)` แล้วแสดงผ่าน `TextView`. ตัวอย่างแยก Activity code, layout XML และ `strings.xml`.
4. **Manifest & theme** (หน้า 14–15): ประกาศ Activity ใน `AndroidManifest.xml`; ตัวอย่าง `MainActivity` เป็น launcher (`android:exported="true"`), `DisplayActivity` เป็น internal (`android:exported="false"`) และกำหนด `android:parentActivityName`. สไลด์ยกตัวอย่างธีม `Theme.Material3.DayNight` แต่ **ไม่ได้ทดสอบการสลับ Day/Night**.
5. **iOS value passing (comparison)** (หน้า 17–20): ตัวอย่างการเปลี่ยน Scene ด้วย navigation/segue และการส่งข้อความไปยัง view controller ปลายทาง; ใช้เป็นภาพเปรียบเทียบ ไม่ใช่ข้อบังคับสำหรับโปรเจกต์ Android.
6. **Touch and multi-touch examples** (หน้า 21): ภาพตัวอย่างวาดเส้นด้วยการสัมผัสและตรวจหลายจุดสัมผัส; **ไม่ปรากฏโค้ดการติดตั้ง listener แบบเต็ม** ในหน้านี้.

**Project application (ข้อเสนอ ไม่ใช่คำกล่าวจากสไลด์):** สำหรับแอปโน้ตเสียง Android/Kotlin สามารถใช้แนวคิด listener กับ Record/Stop/Save, ส่ง `noteId` ระหว่างหน้ารายการกับหน้าโน้ตเมื่อใช้หลาย Activities และจัดการคำสั่ง Clear/Delete ตามนโยบายของแอป; Kotlin/Jetpack Compose อาจใช้ API คนละชื่อกับตัวอย่าง Java/XML แต่หลัก event-driven input → processing → output เชื่อมโยงได้.

**AI guardrails:** อย่าอ้างว่า BM04 สอน Speech-to-Text, Kotlin implementation, Compose navigation หรือการยืนยันการลบ; สิ่งเหล่านี้ต้องอ้างแหล่งอื่นหรือระบุว่าเป็นการประยุกต์. อย่าสรุปว่าการมี `DayNight` ทำให้ผ่าน Rubric โดยไม่มีการทดสอบ และอย่าสร้างผลการทดสอบ/บั๊กขึ้นเอง.
