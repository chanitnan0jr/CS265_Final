# CS265 — BM02: Android Platforms, Activity Lifecycle & Core App Quality

> **Source:** `BM02(1).pdf` (36 หน้า), CS265 ปีการศึกษา 2569  
> **Usage:** AI reference สำหรับ `REQ-1.3`; อ้างเป็น `CS265 BM02, slide N`  
> **Rule:** เนื้อหาจากสไลด์ ≠ หลักฐานว่าโครงงานพัฒนาหรือทดสอบผ่านแล้ว

## Key concepts

1. **Licenses & Android platforms** (หน้า 2–7): แยก proprietary / open source (permissive เช่น MIT, Apache; copyleft เช่น GPL); Android รุ่นต่าง ๆ มี **API level** ต่างกัน; ใช้ **AVD/Emulator** ทดสอบหน้าจอหลายขนาดและความละเอียด
2. **Activity lifecycle** (หน้า 8–9, 18–22): `onCreate` (initialize) → `onStart` (visible) → `onResume` (interactive) → `onPause` (lost focus) → `onStop` (not visible) → `onDestroy` (destroyed); กลับจาก stopped ผ่าน `onRestart`. ต้องจัดการทรัพยากรและรักษาสถานะเมื่อสลับแอป/มีสายเข้า/หมุนจอ; **อย่ารอ `onDestroy` เพื่อบันทึกข้อมูล**. หน้า 10–17 มีตัวอย่าง Dialog และสลับ Activity A/B/C
3. **Back stack** (หน้า 23–26): การนำทางระหว่าง Activity/Fragment ใช้ stack; Back จะ pop ปลายทางตามลำดับ หรือ pop หลายระดับกลับหน้าที่กำหนดได้
4. **State & navigation quality** (หน้า 27–28): รองรับ Back button/gesture; เมื่อกลับจาก Recents, ปลดล็อก หรือเปิดแอปซ้ำ ควรกู้คืนฟอร์ม/ความคืบหน้าที่ค้างให้เหมาะกับบริบท
5. **Visual quality & accessibility** (หน้า 29–32): Notification ใช้ channel/priority/grouping เหมาะสม; UI รองรับ portrait/landscape และการเปลี่ยนแนวจอโดยข้อมูลไม่หาย; ไม่ตัดข้อความ รองรับภาษาที่ให้บริการและ dark theme; touch target **≥48dp**, contrast **3:1** (ตัวใหญ่/กราฟิก) หรือ **4.5:1** (ตัวเล็ก), ใช้ `contentDescription` สำหรับองค์ประกอบ UI ที่เหมาะสม
6. **Performance** (หน้า 33): โหลดเกิน ~2 วินาทีควรมี loading feedback; เป้าหมายการวาดเฟรม ~**16ms/frame** (60fps); หลีกเลี่ยงการบล็อก UI thread, ANR, crash
7. **Privacy & security** (หน้า 34–36): ขอ permissions เท่าที่จำเป็นเมื่อเริ่มใช้ฟีเจอร์ พร้อมรองรับการปฏิเสธ; เก็บข้อมูลอ่อนไหวใน internal storage และไม่ log; ระบุ `android:exported`; สไลด์ระบุการสื่อสารผ่าน SSL และ network security configuration

## Rubric mapping

| Requirement | Link to BM02 | Evidence to verify |
|---|---|---|
| `REQ-1.3` | แนวคิด mobile architecture/lifecycle/quality | อ้างเลขหน้า + โค้ด/ภาพที่แสดงการนำไปใช้จริง |
| `REQ-3.1–3.4` | AVD, orientation, language, dark theme (7, 30–31) | ทดสอบ 2 ขนาดจอ, แนวตั้ง/นอนหรือ lock, ไทย/อังกฤษ, day/night |
| `REQ-4.1–4.2` | Back stack และ state-preserving navigation (23–28) | เส้นทาง Back ทุกหน้าพร้อมทดสอบยกเลิกออกจากงาน; **การยืนยันก่อนออกเป็นเกณฑ์ Rubric** |
| `REQ-4.4` | Pause/resume lifecycle และ state restoration (18–22, 27–28) | สลับแอปแล้วงานหยุดและกลับมาทำต่อได้จริง |
| `REQ-2.2–2.4` | ประเด็นที่ *อาจ* พบ: state loss, UI overflow, ANR | ต้องมีปัญหาจริง → root cause → code fix → before/after |

**Example (ไม่ใช่ข้อกำหนดในสไลด์):** แอปจดโน้ตด้วยเสียงสามารถเชื่อม `onPause/onResume` กับการหยุดงานและคืนสถานะการอัด/ถอดเสียง; เชื่อม Back stack กับหน้ารายการ→แก้ไขโน้ต; เชื่อม permissions กับการขอใช้ไมโครโฟนเมื่อเริ่มอัดเสียง

**AI guardrails:** แยก *Slide fact* จาก *Project application*; Core App Quality เป็นแนวทางคุณภาพ ไม่ใช่การเพิ่มเกณฑ์ให้คะแนน; อย่ากล่าวว่าใช้เทคนิค/แก้บั๊ก/ผ่านเกณฑ์แล้วโดยไม่มีหลักฐานจริง และอย่านำรายละเอียดของบทอื่นมาอ้างเป็น BM02
