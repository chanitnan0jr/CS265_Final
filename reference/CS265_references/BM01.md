## Essential concepts

1. **Device diversity** (หน้า 8–11, 20): อุปกรณ์มีหน้าจอหลายขนาด/ความละเอียด; UI ต้องไม่ถูกตัดหรือซ้อนกัน (เชื่อม REQ-3.1)
2. **Android architecture** (หน้า 12–13): Android ใช้ Linux kernel และมีชั้น framework/runtime/libraries; แอปเข้าถึง sensor, location, SQLite และ API ระบบได้ (REQ-1.3)
3. **Mobile constraints** (หน้า 19–20): อุปกรณ์มีข้อจำกัดด้านจอ/การป้อนข้อมูล/พลังงาน/ประสิทธิภาพ/ความเป็นส่วนตัว; ต้องออกแบบตามบริบทมือถือ (REQ-1.3, REQ-2.x เมื่อมีปัญหาจริง)
4. **Inputs & feedback** (หน้า 20, 35): tap, long tap, swipe, gesture, sound, keyboard; ตอบสนองผ่าน display/vibration/speaker/Toast/Notification/Dialog. ตัวอย่าง `onTouchEvent` อยู่หน้า 35 (REQ-2.1, REQ-4.2–4.3 เมื่อใช้จริง)
5. **Navigation patterns** (หน้า 20): Hierarchy, Flat/Tab, Content-driven/Page Control; ควรเลือก flow ตามงาน (REQ-4.1)
6. **Mobile app types** (หน้า 21–22): Native vs Mobile Web; stand-alone vs cloud/API-backed และรูปแบบรายได้/บริการ (REQ-1.3)
7. **Examples** (หน้า 24–63): ภาพตัวอย่างแอปยอดนิยมและโครงงานเก่า; เป็นแรงบันดาลใจ ไม่ใช่ requirement ของโครงงานปัจจุบัน
